# APEX AutoLab Reception — Back-end 1.0

Навчальний прототип для приймання автомобілів на СТО. Автор роботи: Яковенко Олександр Володимирович, КН-41. Практичне заняття 15 (у тексті завдання платформи також зазначено №16).

## Що реалізовано

- Локальний REST API: клієнти, автомобілі, замовлення та історія статусів.
- SQLite, зовнішні ключі, транзакції й унікальний індекс одного активного наряду на авто.
- Нормалізація номера; повторний заїзд повертає активний наряд без перезаписування.
- Блокування готовності й початку робіт без клієнта, телефону, опису та підтвердження.
- Один оператор: хеш пароля scrypt, серверне відкликання сесій, CSRF, обмеження спроб входу.
- Локальне OCR фотографії через Tesseract, ручне введення через API при помилці OCR.
- JPEG/PNG-вкладення, резервні копії бази з фото та перевірене офлайн-відновлення.

Це серверна частина. Графічний Front-end, інсталятор, відеопотік камери, ROApp та пошук власника за номером не реалізовані. Сервер не надсилає дані зовнішнім сервісам. API готовий для підключення локального інтерфейсу.

## Запуск

Потрібен Python 3.12. Перевірено Python 3.12.14/Linux; запуск Windows/macOS ще потребує окремого випробування. Для першого встановлення пакетів потрібен інтернет. Команди виконуються з каталогу проєкту.

Windows, PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe manage.py init-admin --username operator
.\.venv\Scripts\python.exe manage.py serve
```

macOS, Terminal:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python manage.py init-admin --username operator
.venv/bin/python manage.py serve
```

Пароль вводиться приховано двічі; мінімум 12 символів. У комплекті немає готового облікового запису або реальних клієнтських даних. Сторінка `http://127.0.0.1:8765/api/health` має повернути JSON `{"status":"ok","version":"1.0.0"}`. Корінь `/` повертає відомості про API, а не графічну форму. Зупинка: Ctrl+C.

Зміна порту: `python manage.py serve --port 8766`. Окремий каталог даних: `python manage.py --data-dir /absolute/path/to/data serve` (параметр перед підкомандою). На Windows шлях із пробілами взяти в лапки. За замовчуванням дані лежать у `instance/`.

### OCR

Окремо встановити Tesseract і мовні дані `eng` за [офіційною інструкцією](https://tesseract-ocr.github.io/tessdoc/Installation.html). Перевірити `tesseract --version`. Виконуваний файл має бути у PATH; альтернативно задати `APEX_TESSERACT` його повним шляхом до запуску. У середовищі перевірки використано Tesseract 5.3.4. Без нього облік продовжує працювати, `/api/ocr` повертає 503 і пропонує ручне введення.

OCR обробляє однорядковий номер на фото або область, задану `crop`. Автоматичного детектора рамки номера немає. Результат потрібно перевірити: OCR ніколи самостійно не створює авто чи наряд.

## Структура

| Файл | Призначення |
|---|---|
| `manage.py` | CLI: оператор, сервер, копія, відновлення |
| `apex/__init__.py` | Фабрика Flask, middleware, JSON-помилки |
| `apex/db.py`, `schema.sql` | З’єднання, транзакції, схема БД |
| `apex/routes.py` | REST-маршрути та CRUD |
| `apex/orders.py` | Приймання та переходи статусів |
| `apex/validation.py` | Перевірка типів, номера, VIN, телефона |
| `apex/auth.py` | Вхід, CSRF-токен, сесії, ліміт спроб |
| `apex/media.py` | Перевірка фото, OCR, вкладення |
| `apex/backup.py`, `locking.py` | Архіви та блокування процесу |
| `docs/API.md` | Контракт API й приклади |
| `tests/`, `tools/smoke.py` | Автоматичні та HTTP-перевірки |

Використано стандартний `sqlite3`, без ORM: запити параметризовані, таблиці й поля обираються з внутрішніх списків. ORM в умові рекомендований, але не обов’язковий. Так зберігається стек попереднього ТЗ без додаткової залежності.

## Копії та відновлення

Під час роботи API: `POST /api/backups`, отриманий архів можна завантажити через `GET /api/backups/{id}`. Через CLI, коли сервер зупинено:

```bash
python manage.py backup
python manage.py restore /absolute/path/to/backup.zip --confirm
```

`--confirm` потрібен, бо відновлення замінює поточні дані. Спочатку перевіряються структура ZIP, розмір, SHA-256, схема, цілісність SQLite і зовнішні ключі; після цього створюється страхувальна копія поточного стану. Архів має бути створений цією версією застосунку. SHA-256 перевіряє цілісність, але не автентичність походження; використовувати власні довірені копії. Блокування процесу забороняє відновлення під час роботи сервера. Сесії після відновлення недійсні, потрібен повторний вхід. Пароль оператора відновлюється разом із базою.

Копії містять контакти та фото, не зашифровані. Доступ до каталогу даних і зовнішніх копій потрібно обмежувати засобами ОС. На Windows необхідно перевірити ACL каталогу облікового запису; POSIX-права не є заміною Windows ACL. Ліміт прототипу — 512 МБ даних одного архіву. Автоматичного очищення старих копій і міграції схеми між версіями поки немає.

## Перевірка

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q --junitxml=test-results.xml
python tools/smoke.py smoke-results.json
```

Для smoke-перевірки потрібен Tesseract із `eng`. Скрипт запускає справжній Waitress на вільному loopback-порту, працює з тимчасовою базою, завершує процес і видаляє тестові дані. Pytest не потребує встановленого OCR: відповідні гілки перевіряються підмінами залежностей.

Фактичні результати поставки: `test-results.xml`, `test-results.txt`, `smoke-results.json`, `docs/TESTING.md`. Синтетичне зображення в smoke-тесті не підтверджує точність на реальних автомобілях. Перевірки Windows/macOS, 30 реальних фото та навантаження 5 000 авто/20 000 нарядів ще не виконані.

## Межі використання

Один локальний оператор і один серверний процес; запускати через `manage.py`, щоб діяло блокування. Waitress слухає лише `127.0.0.1`; Host і адреса клієнта перевіряються. Не налаштовувати публічний тунель чи проксі до цього прототипу. Cookie має HttpOnly і SameSite=Strict; Secure вимкнений для локального HTTP. Для мережевого розгортання потрібні окрема модель доступу, HTTPS і перегляд налаштувань.

Номер підтверджує оператор; він не доводить особу власника. Зміна клієнта у наряді не змінює автоматично клієнта в картці автомобіля: для наступних візитів картку слід оновити окремо. Після готовності наряд зберігає знімок імені й телефона; редагування довідника не змінює цей знімок. Резервування й OCR серіалізують запити зміни даних, що прийнятно для одного оператора. Інші користувачі ОС із доступом до файлів лежать поза моделлю захисту API.
