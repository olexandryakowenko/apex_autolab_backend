## Справжній HTTP і OCR

Команда: `python tools/smoke.py smoke-results.json`. У тесті використано справжній процес Waitress і стандартний HTTP-клієнт Python з cookie. База та контакти тестові, тимчасові.

| Перевірка | Отриманий результат |
|---|---|
| Health | HTTP 200 |
| Створення наряду | HTTP 201 |
| Повтор того самого номера | HTTP 200; той самий id |
| Послідовність статусів | ready → in_progress → completed |
| Створення резервної копії | HTTP 201 |
| Спроба відновлення при активному сервері | Заблокована |
| Синтетичне зображення AA1234BB | OCR: AA1234BB |
| Один вимір HTTP OCR | 0,130 с |

Один вимір на синтетичному зображенні підтверджує працездатність зв’язку API–Pillow–Tesseract. Він **не є** оцінкою точності на реальних фото чи показником p95 продуктивності.

## Що ще потрібно перевірити

Windows 11/macOS 13+, їхні права доступу до файлів, установлення OCR та роботу браузерного інтерфейсу; 30 реальних денних фото з ТЗ; швидкодію на 5 000 автомобілів і 20 000 нарядів; збої живлення при заміні каталогу під час відновлення; інтеграцію з Front-end. Ці умови не позначені виконаними. Тести резервування охоплюють штатне відновлення та перевірку недійсних архівів, але не фізичний збій носія.

Загальний висновок: реалізований локальний Back-end пройшов перелічені функціональні й інтеграційні перевірки в Linux. Це не твердження про завершення всього продукту або всіх критеріїв ТЗ.
